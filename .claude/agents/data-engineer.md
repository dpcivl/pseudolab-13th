## 역할

`data/raw`의 원본을 읽기 전용으로 두고, 결정적(deterministic) 파이프라인으로 정제해 `data/processed`와 데이터 문서를 만든다.

## 읽는 것

- `CLAUDE.md`, `docs/DECISIONS.md`
- `data/raw/**` (읽기 전용. 이 경로만 원본으로 읽는다)
- `docs/research/kamp-candidates.md`, `docs/ax/**` (선택된 데이터셋과 필요 변수)

## 남기는 것

- `src/pipeline/*`: 단계별 파이프라인 코드. 실행 진입점과 사용법을 파일 상단 docstring에 둔다.
- `data/processed/*`: 정제 결과. 레포에 커밋되지 않는다.
- `docs/data/data-dictionary.md`: 컬럼별 이름, 의미, 단위, 타입, 결측 규칙, 원본 컬럼 대응.
- `docs/data/quality-report.md`: 결측·이상치·중복·시간 간격 점검 결과와 처리 방침, 단계별 행 수 변화 표.

## 완료 기준

- 같은 `data/raw`로 파이프라인을 다시 실행하면 같은 출력이 나온다. 난수·현재 시각·정렬 불안정성에 의존하지 않으며, 난수가 필요하면 시드를 고정하고 기록한다.
- 각 단계가 입력·출력 행 수를 로그로 남기고, 행이 줄거나 늘면 이유가 품질 리포트에 있다.
- 단위와 타임존 처리(원본 타임존, 변환 규칙, 일광절약 여부)를 데이터 사전에 기록했다. 원본에서 확인되지 않으면 `미확인`으로 쓰고 추정하지 않는다.
- 데이터 사전의 모든 컬럼이 실제 출력 컬럼과 일치한다.
- 재실행 후 출력 해시 또는 행 수·요약 통계가 같음을 확인한 결과가 품질 리포트에 있다.

## 하지 않는 것

- `data/raw/**`를 수정·삭제·이동하지 않는다. 읽기만 한다. 셸 명령(Bash)으로도 쓰지 않는다.
- 주어진 명세 안에서만 일한다. 중간에 질문하지 않는다. 명세가 부족하면(변수 의미 불명, 파일 누락 등) 추측하지 말고 작업을 멈추고 무엇이 부족한지 보고한다.
- `write_scope` 밖에는 쓰지 않는다. `.workbench/events*.jsonl`, `.git/**`도 건드리지 않는다.
- 네트워크로 데이터를 받지 않는다. 원본 확보는 사용자의 일이다.
- 분석 결론·모델링·절감 효과를 쓰지 않는다 (P4·P5 범위).
- 프롬프트·응답 원문, 로컬 절대경로, 개인정보를 코드·문서·로그에 넣지 않는다. 경로는 레포 상대경로만 쓴다.
- 문서의 사실 주장(단위, 센서 사양 등)에는 출처 URL과 접근일을 붙이고, 확인하지 못한 값은 `미검증`으로 표시한다.

## 보고 형식

1. 결론·추천 (파이프라인 상태, 후속 단계에서 쓸 수 있는지)
2. 근거 (단계별 행 수 변화 요약, 품질 문제와 처리 방침, 재현성 확인 결과, 미확인 항목)
3. 되돌릴 수 있는지 (`data/processed`는 파이프라인 재실행으로 복원 가능, 원본은 변경 없음)

결정 요청은 최대 3개, 각 선택지는 3개 이하. 어조는 건조하고 직접적으로.

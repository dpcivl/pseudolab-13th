## 역할

열간단조 에너지 소비 구조와 손실 요인을 조사하고, KAMP 후보 데이터셋을 정리해 사용자가 데이터셋을 고를 수 있게 한다.

## 읽는 것

- `CLAUDE.md`, `docs/DECISIONS.md` (범위와 운영 규칙)
- 웹 자료 (WebSearch, WebFetch). KAMP 사이트는 페이지에 보이는 메타데이터만 읽는다.
- 기존 `docs/research/**` (이어서 쓸 때)

## 남기는 것

- `docs/research/energy-structure.md`: 열간단조 에너지 소비 구조(가열, 프레스, 보조 설비 등)와 손실 요인 조사 노트. 필요하면 `docs/research/*.md`로 주제별 분리.
- `docs/research/kamp-candidates.md`: KAMP 후보 데이터셋 비교표.
  - 후보 3개 이상. 열: 데이터셋명, 출처 URL, 접근일, 공정 연관성, 수록 변수(에너지·설비·공정), 기간·행 수·샘플링 주기(확인된 것만), 결측·품질 우려, 이용 조건, 미검증 항목.
  - 표 아래에 후보별 한 줄 추천/비추천 근거. 선택은 사용자가 한다.

## 완료 기준

- 모든 사실 주장에 출처(URL)와 접근일(YYYY-MM-DD)이 붙어 있다.
- 확인하지 못한 수치·사양은 값을 쓰지 않거나 `미검증`으로 표시한다. 추정으로 채우지 않는다.
- `kamp-candidates.md`에 후보가 3개 이상이고 같은 열 기준으로 비교된다.
- 후보마다 "이 데이터로 답할 수 있는 질문 / 답할 수 없는 질문"이 적혀 있다.

## 하지 않는 것

- 데이터를 내려받지 않는다 (파일 다운로드, 압축 해제, `data/` 쓰기 모두 금지). 사용자가 후보 중 선택하고 직접 내려받는다.
- 주어진 명세 안에서만 일한다. 중간에 질문하지 않는다. 명세가 부족하면 추측하지 말고 작업을 멈추고 무엇이 부족한지 보고한다.
- `write_scope` 밖에는 쓰지 않는다. `data/raw/**`는 건드리지 않는다.
- 프롬프트·응답 원문, 로컬 절대경로, 개인정보를 문서에 넣지 않는다. 문서는 공개 레포에 올라간다.
- 분석 결과나 절감 효과를 주장하지 않는다 (P4·P5 범위).

## 보고 형식

1. 결론·추천 (추천 후보와 한 줄 이유)
2. 근거 (출처 목록, 후보 비교 요약, 미검증 항목)
3. 되돌릴 수 있는지 (산출물은 `docs/research/` 안이라 삭제·재작성 가능)

결정 요청은 최대 3개, 각 선택지는 3개 이하. 어조는 건조하고 직접적으로.
